# Moros workbench

The right workbench is an auxiliary task surface. The Sidebar still owns navigation and the center still owns the conversation. The panel starts closed, uses one compact tab row, and pushes the conversation on desktop. Below 1100 px it becomes a drawer; below 600 px it fills the available area. Width, tab order, active tab, collapsed state and pending feedback are persisted separately for each workspace/session.

## Modules and transport

- `src/shared/workbench.ts` and `workbench-contract.ts` define action-specific validated requests with a request-to-response type mapping. Files home is a `files` resource; saved legacy empty-file tabs migrate on load. `MorosApi.workbench` uses the existing Electron IPC and Web RPC/SSE registry.
- `src/main/workbench/service.ts` owns scope authorization, resource identity, operations and confirmations. File grants are created by explicit native picker selection and are stored outside renderer-owned state.
- `files.ts`, `terminals.ts`, `browser.ts`, `review.ts` and `review-provenance.ts` own their respective backend boundaries.
- `src/renderer/src/workbench` implements views, a Zustand slice, dialogs, feedback and keyboard behavior. Its CSS is separated from the existing application styles.

## Supported surfaces

The Files entry opens a workspace file browser directly: search and recent files on the left, an expandable directory tree on the right. Recents survive closing tabs and are persisted per scope. Search covers real names in nested directories, excludes dependency/cache internals and is bounded to 10,000 inspected entries and 100 matches. Explicit New file/New folder actions use exclusive creation within the canonical workspace and cannot overwrite an existing entry. Opening a file preserves the tree and offers Back to files; its contents remain read-only.

Files are read-only. CodeMirror provides syntax coloring, line numbers, folding, searching, line jumps and optional wrapping. Markdown has source/rendered modes; local links resolve relative to the containing document. Images zoom; PDF.js renders paginated PDFs. Mammoth previews DOCX content after bounded archive validation. Unsupported formats offer an explicit explanation and a system-app action. Text is capped at 2 MB and binary previews at 25 MB. File changes produce a refresh notice; the user decides when to refresh.

HTML file previews disable scripts. Interactive HTML opens in the isolated browser and is served through a random, scope-bound capability URL. Workspace artifacts can load relative static assets within their directory. An external file chosen with the native picker grants only that exact file, and the UI explains that neighbouring scripts, styles and images cannot load. Hidden files, JSON and unsupported assets are not served. Artifact pages cannot make external network requests or navigate to other origins. Apps that need a backend, remote dependencies or origin-root asset paths should run through their own development server.

Terminals are real `node-pty` processes owned by the main process. xterm handles input, selection, copy/paste, scrollback and size. Output uses monotonically increasing offsets with a retained 1-million-character buffer. Renderer reloads, switching tabs and changing conversations do not terminate PTYs. Closing a live terminal requires a scoped one-use confirmation. Quitting the main application ends its owned terminal processes; restored tabs then report that their process is unavailable. No external process is adopted or killed.

The Electron browser uses sandboxed `WebContentsView` instances and dedicated per-session storage partitions. It never imports system-browser cookies or profiles, denies downloads and permission requests, blocks local-file protocols and Moros control endpoints, and exposes no Node or Moros API to page scripts. Metadata includes title, URL, navigation/loading state and bounded console errors. Element/region annotations use actual trusted pointer input and native page capture. Web browsers cannot safely supply this native surface: the Web version explains the limitation and offers opening the URL in a separate browser tab. Files, terminals, Review and pending feedback use the same backend in both clients.

Git Review reads actual unstaged, staged, branch, commit and last-turn state. Requested paths resolve relative to the workspace (absolute paths also work) and become literal Git pathspecs before diff generation and untracked-file enumeration. Unrelated files cannot exhaust a single-file review's limits. Whole diffs, files and supported text hunks can be staged/unstaged. Revert is available for unstaged changes and requires a one-use, two-minute confirmation tied to the exact diff version and selected paths/hunk. A changed diff rejects the operation. Historical ranges are read-only. Renames and binary changes use whole-file actions.

Last-turn provenance captures the working tree before and after an Agent turn. It conservatively separates pre-existing dirty content, confirmed write/edit results, mixed modifications and other/unattributed work. Shell or concurrent writes are not claimed as Agent-owned. The in-memory baseline is bounded to 3,000 files, 2 MB per file and 30 MB total; unsupported/binary entries are explicitly excluded. Restarting the main process clears the baseline and shows an unavailable explanation until another turn starts.

## Feedback and Agent tools

File comments, browser annotations and Review line comments enter one pending tray. They do not trigger a prompt. The user selects, removes or sends them with the next message. The backend consumes only the supplied IDs atomically and restores them if the prompt is rejected before entering the conversation. The structured payload distinguishes explicit `user_comment` from `untrusted_evidence`. Screenshots accompany image-capable models within the existing attachment count limit; other models receive text and location information.

State changes commit to the in-memory cache and emit events only after the atomic disk rename succeeds. A failed tab save cleans up only its newly created runtime; a failed close leaves the existing terminal running. Read failures do not silently replace saved state. Retained and live terminal output share one monotonic cursor, including while a snapshot or xterm write is pending.

Queue recall transfers a complete `UserMessageDraft` (text/skills, images and feedback) back to the originating session. The recalled feedback appears in the same pending tray and is submitted only when selected by the user. Original image names and annotation screenshots follow the actual queue entry through weakly owned UI metadata, without adding them to model text. Legacy queue entries recover their actual text/images and serialized comment metadata. Recalled drafts and their pending feedback survive tab/session/settings switches in renderer memory, like other unsent Composer drafts; they do not survive a full renderer reload. A rejected re-send retains the draft and recalled feedback. `prompt-submission.ts` owns preparation and preflight acceptance; `user-message.ts` owns display/draft projection so skill parsing does not also parse workbench feedback.

Agent extensions expose `workbench_open`, `workbench_terminal_read`, `workbench_terminal_command`, `workbench_browser_inspect` and `workbench_review_read`. Scope comes from the active Agent context, never tool parameters. Pending comments are not returned by these tools. Terminal input is marked Agent/user at the trusted transport boundary. Agent terminal input always goes through the existing approval path outside Full access, including commands that look read-only, because the foreground terminal process may not be a shell. Agent Review tools cannot stage or revert.

## Keyboard and validation

Ctrl+Alt+P focuses the panel; Ctrl+Tab cycles tabs; Ctrl+W closes the active tab within the panel; Esc returns to chat. Alt+Shift+Left/Right reorders the focused tab. The divider supports arrows, Home and End. Ctrl+Shift+P opens a file, Ctrl+T opens a browser tab, Ctrl+backtick opens a terminal, and Ctrl+Shift+G opens Review. Chat retains Ctrl+P/Ctrl+K session search; Ctrl+P within the panel opens files. Labels cover Simplified Chinese, Traditional Chinese, English and German.

Run `npm run typecheck`, `npm run test:unit`, `npm run audit:providers:static`, `npm run build`, `npm run test:smoke` and `npm run test:workbench`. The workbench smoke uses a temporary Git repository, isolated Electron/Pi profiles, native PTYs, a local HTTP fixture, document artifacts and headless Chrome for Web RPC. No real model prompt is sent; Git commits exist only in the disposable fixture repository.
